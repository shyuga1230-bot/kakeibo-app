# 見積もり併売データベース

受注した見積もり(案件)を1件ずつ蓄積し、**「Aが売れた案件ではBも売れやすい」という組み合わせ(併売)を数字で確認できる**社内向けWebアプリです。

| 画面 | できること |
|---|---|
| **登録** | 見積もり1件ずつの登録/Excel見積書(鑑)の貼り付けによる自動入力/一覧の貼り付けによるまとめて登録 |
| **併売分析** | 基準項目を選んで併売率を表示/定番の組み合わせTOP10/売れ筋ランキングTOP10 |
| **履歴** | 登録済み見積もりの一覧(新しい順)・編集・削除(2段階確認) |

- すべての画面の上部に「登録件数・取扱項目数・併売ペア数・合計金額」を常時表示します。
- データはサーバーのデータベース(PostgreSQL)に保存され、**全員で共有**されます。別の人が登録した内容は、画面を再読み込みすると反映されます。
- 全社共通のパスワード1つでログインします。
- PCでもスマホでも使えます。

> **併売率の定義**: 基準項目Aを含む案件数を N、AとBの両方を含む案件数を n としたとき、Bの併売率 = n ÷ N。1案件内に同じ項目が複数あっても1回と数えます。

## 1. 必要なもの

- **Node.js 22以上**(無料)
  - [https://nodejs.org/ja](https://nodejs.org/ja) から「LTS(推奨版)」をダウンロードしてインストールしてください。
  - インストールできたかは、ターミナル(Windowsは「コマンドプロンプト」)で `node -v` と打って数字が出れば OK です。

## 2. 初期設定(手元のPCで動かす)

何も入っていない状態から、次の順番で進めてください。

### 手順1: このフォルダを開く

ターミナルでこのアプリのフォルダに移動します。

```bash
cd kakeibo-app
```

### 手順2: 必要な部品をインストール

```bash
npm install
```

### 手順3: 設定ファイルを作る

```bash
cp .env.example .env        # Windowsの場合: copy .env.example .env
```

作成された `.env` ファイルをメモ帳などで開き、**`APP_PASSWORD` を全社共通のパスワードに変更**してください。それ以外は最初はそのままで大丈夫です。

### 手順4: データベースを起動する

**別のターミナルを開いて**、次を実行します(このターミナルは開いたままにします)。

```bash
npm run db:up
```

初回は少し時間がかかります。「now running」と表示されたら起動完了です。

### 手順5: データベースの中に表を作る

元のターミナルに戻って:

```bash
npm run db:push
```

### 手順6(任意): 動作確認用のサンプルデータを入れる

架空の見積もり20件が入ります。使い方の確認におすすめです。

```bash
npm run db:seed
```

### 手順7: アプリを起動する

```bash
npm run dev
```

ブラウザで **http://localhost:3000** を開き、`.env` に設定したパスワードでログインできれば完成です。
同じネットワーク内の他のPCやスマホからは `http://(このPCのIPアドレス):3000` で開けます。

> 2回目以降の起動は「手順4(別ターミナルで `npm run db:up`)→ 手順7(`npm run dev`)」だけで OK です。

## 3. 本番運用(Vercel + クラウドデータベース)

社外からも使えるようにする場合や、常時稼働させる場合は Vercel(ホスティング)+ Neon(データベース)の組み合わせが簡単です(どちらも無料枠あり)。

1. このリポジトリを GitHub に置き、[Vercel](https://vercel.com) で「New Project」からインポートします。
2. Vercel のプロジェクト画面 → **Storage** タブ → **Neon (Postgres)** を追加します。
   - 接続情報(`DATABASE_URL`)は自動で設定されます。
3. プロジェクトの **Settings → Environment Variables** で次の2つを追加します。
   - `APP_PASSWORD` : 全社共通のログインパスワード
   - `SESSION_SECRET` : ランダムな長い文字列(ターミナルで `openssl rand -base64 32` を実行して作れます)
4. **Deploy** を押します。デプロイ時に自動でデータベースの表が作られます(`npm run build` の中で実行されます)。

> **先にデプロイしてしまった場合**: データベースやパスワードを設定する前でもデプロイ自体は成功しますが、画面を開くと設定を促すエラーメッセージが表示されます。上記2〜3の設定を行ったあと、Vercel の Deployments 画面から「Redeploy」を実行してください。

> Neon 以外でも、`postgres://` で始まる接続URLが使えるデータベース(Supabase、自社サーバーの PostgreSQL など)なら、`DATABASE_URL` を差し替えるだけで動きます。**接続先の切り替えはすべて環境変数で行い、プログラムの変更は不要です。**

### 社内サーバーで動かす場合

PostgreSQL が入ったサーバーであれば次でも運用できます。

```bash
npm install
# .env に DATABASE_URL / APP_PASSWORD / SESSION_SECRET を設定
npm run build
npm run start        # http://サーバーのアドレス:3000
```

> **注意**: https を使わず社内ネットワークの http のまま運用する場合は、`.env` に `SESSION_COOKIE_SECURE="false"` を追加してください(これがないとログインが維持されません)。

## 4. 使い方のポイント

### 登録画面

- **Excelの見積書からの自動入力**: Excelで見積書の表紙(鑑)のシート全体を選択してコピーし、「見積書(Excel)から自動入力」の枠に貼り付けて「見積書を読み取ってフォームに入れる」を押すと、日付・顧客名・工事名・項目・金額が自動でフォームに入ります。経費(現場管理費・一般管理費など)や合計の行、項目名の丸数字(①②…)は自動で除外・整理されます。内容を確認してから登録ボタンを押してください。
- 日付は自動で今日になります。顧客名・金額・メモは空欄でもかまいません。
- 項目名は、過去に登録した名前が入力候補として出ます。**表記ゆれ(全角/半角スペースなど)は保存時に自動でそろえられます。**
- 金額は「1,200,000」「¥1200000」「全角数字」のままでも登録できます。
- Enter キーでは登録されません(日本語変換の確定で誤登録しないため)。登録は必ず青いボタンで行います。

### まとめて登録(貼り付け取込)

Excel などで作った一覧を貼り付けて一度に登録できます。**1行が1件**になります。

```
日付, 顧客名, 項目(/区切り), 金額(省略可・/区切りで項目に対応)
```

例:

```
2026/6/1, 山田建設, 3D起工測量/ICT建機レンタル, 500000/1200000
2026-06-03, , 操作講習, 80000
2026/6/5, 佐藤工務店, 3D起工測量/操作講習/ソフトウェア, 450000//300000
```

- 区切りはカンマまたはタブ(Excel からコピーして貼り付けるとタブになります)。
- 日付は `2026/6/1`・`2026-06-01`・`2026年6月1日` などの書き方に対応しています。
- エラーのある行は**行番号と理由**が表示され、正常な行だけが登録されます。

### 併売分析画面

- 左のリストから基準項目を選ぶと、一緒に売れている項目が「n/N件・併売率%」で表示されます。
- 売れ筋ランキングの項目名を押すと、その項目を基準にした分析に切り替わります。
- 登録件数が少ないうちは割合がぶれやすいので、目安として見てください。

### 履歴画面

- 削除は確認画面付きです。**削除すると全員のデータから消え、元に戻せません。**
- 「編集」から登録済みの内容を修正できます。

## 5. バックアップ

### 方法1: CSVで保存(いちばん簡単・全員できる)

画面右上の「**CSVを保存**」ボタンを押すと、全データが CSV ファイルでダウンロードされます。Excel でそのまま開けます(文字化けしません)。**週に1回など、定期的に保存しておくことをおすすめします。**

### 方法2: データベース自体のバックアップ(管理者向け)

- **Neon を使っている場合**: Neon のダッシュボードに履歴からの復元機能(Restore)があります。また「Branches」機能でその時点のコピーを作れます。
- **自社の PostgreSQL の場合**: 定期的に `pg_dump` を実行してファイルを保管してください。

```bash
pg_dump "$DATABASE_URL" > backup_$(date +%Y%m%d).sql
```

> ローカルの簡易データベース(`npm run db:up`)は動作確認用です。本番データは Neon などのクラウドデータベースに置くことをおすすめします。

## 6. よくあるトラブルと対処

| 症状 | 原因と対処 |
|---|---|
| ログイン画面で「サーバーにパスワードが設定されていません」と出る | `.env`(Vercel の場合は Environment Variables)に `APP_PASSWORD` が設定されていません。設定して再起動してください。 |
| パスワードを変えたら全員ログインし直しになった | `SESSION_SECRET` を設定していない場合の正常な動作です(パスワードが鍵を兼ねるため)。`SESSION_SECRET` を設定すると、パスワード変更後もログインが維持されます。 |
| 「エラーが発生しました」と表示される | データベースに接続できていない可能性が高いです。ローカルの場合は `npm run db:up` のターミナルが動いているか、`.env` の `DATABASE_URL` が正しいかを確認してください。 |
| ログインしてもすぐログイン画面に戻される(http運用) | `.env` に `SESSION_COOKIE_SECURE="false"` を追加して再起動してください。 |
| `npm run dev` で「port 3000 is in use」と出る | 別のアプリが3000番を使っています。`PORT=3001 npm run dev` のように番号を変えて起動してください。 |
| 他の人の登録が見えない | 画面を再読み込みしてください(ブラウザの更新ボタン)。 |
| 「ログインの失敗が続いたため…」と出る | パスワードを5回続けて間違えると、1分間ログインを受け付けなくなります(総当たり対策)。1分待ってから正しいパスワードで入り直してください。 |
| 間違えて削除してしまった | 削除は元に戻せません。CSVバックアップを開いて内容を確認し、登録画面から入力し直してください(まとめて登録を使う場合は、CSVの内容を「日付, 顧客名, 項目/項目, 金額/金額」の形に並べ替えてから貼り付けます)。 |
| CSVをExcelで開くと日付が変わってしまう | Excel の仕様で「2026-04-02」が日付形式に変換されることがあります。列の書式を「文字列」にして開くか、そのまま使って問題なければ気にしなくて大丈夫です。 |

## 7. 開発者向けメモ

### 技術構成

- Next.js 16(App Router)+ TypeScript + Tailwind CSS v4
- PostgreSQL + Prisma 7(接続は `@prisma/adapter-pg`、接続先は `DATABASE_URL` で切り替え)
- 認証: 全社共通パスワード(`APP_PASSWORD`)+ 署名付きCookie(`jose`)。`src/lib/session-token.ts` の `SessionPayload.user` を拡張すればユーザー別アカウントに移行しやすい構造です。
- ※ この Next.js のバージョンでは `middleware.ts` は `proxy.ts` に名前が変わっています(認証ゲートは `src/proxy.ts`)。

### 主なフォルダ

```
prisma/            データベースの設計図とマイグレーション
scripts/seed.ts    サンプルデータ投入
src/proxy.ts       認証ゲート(未ログインをログイン画面へ)
src/app/           画面(/ 登録、/analysis 分析、/history 履歴、/login)とAPI
src/app/actions.ts 登録・編集・削除・取込・ログインのサーバー処理
src/lib/           共通処理(DB接続・セッション・正規化・併売計算・CSV)
src/components/    画面の部品(フォーム・削除ダイアログなど)
tests/             計算処理の自動テスト
```

### コマンド

| コマンド | 内容 |
|---|---|
| `npm run dev` | 開発サーバー起動(http://localhost:3000) |
| `npm run db:up` | ローカル簡易データベース起動(開発用) |
| `npm run db:push` | データベースに表を作成/更新(開発用) |
| `npm run db:seed` | サンプルデータ20件を投入 |
| `npm test` | 計算処理(正規化・併売率・CSV)の自動テスト |
| `npm run build` | 本番ビルド(マイグレーション適用を含む) |
| `npm run start` | 本番サーバー起動 |
